Branch 03

Evaluation for AI systems that make decisions.

I am interested in LLMs less as static text generators and more as systems that choose, adapt, retrieve, generate candidates, and act under an evaluation protocol.

LLM policies adaptive systems trustworthy tests
Core question

What does it mean for an adaptive AI system to perform well?

A single benchmark score often hides the decision process. This branch asks how to evaluate systems whose behaviour depends on prompts, candidate generation, memory, feedback, and the structure of the task they are given.

Question

When should an agent trust retrieved experience?

External memory can help, do nothing, or cause negative transfer. The evaluation task is to identify when reuse adds value and when the system should abstain or intervene.

Method lens

Evaluation should expose the controller.

Useful experiments should separate retrieval, initial memory choice, runtime monitoring, suppression, and replanning rather than compressing everything into one score.

Related work

Selective reuse under uncertainty.

My SUSTech research uses paired policy comparisons to study when retrieved cases help or harm an LLM agent. Current evidence is limited to a controlled local mechanism; realistic benchmark validation remains open.
